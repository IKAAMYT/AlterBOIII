====================================================================

  vieux renderer MSHTML/feuilles de styles hacks.
  - SDK WebView2 vendorisé dans deps/Microsoft.Web.WebView2/
    (build/native/include + x64). ~11 Mo. A NE PAS SUPPRIMER :
    premake5.lua le référence pour compiler la logique WebView2.
  - Le pont JS <-> C++ passe par getExternal() (Proxy
    chrome.webview.hostObjects.sync.external sous WebView2, fallback
    window.external sous Wine/MSHTML). Les window.external. ont été
    remplacés par getExternal(). dans data/launcher/main.html et main.js.
  - Les nouvelles fonctionnalités launcher d'Ezz (binds, diagnostics,
    repair workshop, clearProfile, isWine, launcher settings,
    friend identity) sont exposées côté C++ mais n'ont PAS encore leur
    section dans l'UI fork : l'UI garde le visuel/branding AlterBO3.
  - ui_rev.txt = 82 (launcher auto-update de l'UI).

====================================================================
  COMMENT L'APPLIQUER (IMPORTANT)
====================================================================
  Ce merge remplace BEAUCOUP de fichiers. Méthode la plus sûre :

  METHODE RECOMMANDEE (branche de test) :
  1. Sur GitHub, crée une nouvelle BRANCHE (ex: "merge-ezz") depuis ta
     branche main.
  2. Dézippe ce ZIP sur ton PC.
  3. Upload/remplace les dossiers src/ et data/ + premake5.lua (+ le
     dossier deps/Microsoft.Web.WebView2 aimé) dans cette nouvelle
     branche (via GitHub web ou GitHub Desktop).
  4. Lance le workflow de build SUR CETTE BRANCHE.
  5. Si le build est VERT et que le jeu marche -> merge la branche dans
     main.
  6. Si le build ECHOUE -> tu n'as rien cassé sur main, on debug la
     branche ensemble.

  Ne remplace PAS directement main : si une erreur de compilation
  passe (impossible à tester en local), tu casserais ta version live.

CE QUI N'EST PAS DANS LE ZIP (à ne pas toucher) :
  * deps/ autres que WebView2 (submodules Git : Steamworks, curl,
    imgui...) se récupèrent automatiquement via git submodule
  * old-dll/ (vieux binaires, inutiles au build)
  * .git/ (historique)

====================================================================
  RISQUE HONNÊTE
====================================================================
Le gros risque = une erreur de compilation due à la refonte
structurelle d'Ezz (nouveau symbol.hpp, structs déplacés) + à la
migration WebView2. Vérifié :
  * Tous les includes des fichiers IKAAM résolus
  * symbol.hpp (que ton game.hpp utilisait inline) bien présent
  * Pas de fichier orphelin (ancien quake.hpp, strlcpy supprimés)
  * Le premake compile par glob -> prend les 16 nouveaux fichiers auto
  * SDK WebView2 vendorisé ET référencé dans premake5.lua
  * Callbacks launcher cohérents (47 upstream + 4 fork-only exposés ;
    13 méthodes JS utilitaires restent des appels optionnels/inoffensifs)
Mais impossible de compiler ici, donc le build GitHub reste le juge
final. D'où la branche de test.
